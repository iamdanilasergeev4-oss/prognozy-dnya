## Что можно проверить в этой ветке

1. Пробный режим собирает календарь через текущие адаптеры и отдельно сверяет идентичность, время, состояние, турнир, известные сезоны и счёт. Даты openfootball учитываются как подсказки без времени старта. Источники и результаты запросов записываются в диагностику.
2. Статистический расчёт разделён по виду спорта, турниру, сезону и правилам. Параметры Elo отличаются по видам спорта. Для футбола предусмотрены ничья и опциональное домашнее преимущество. Для баскетбола и хоккея учитывается разница счёта. Для тенниса и волейбола учитываются завершённые сеты, для CS2 и Dota 2 требуется формат серии и подтверждённый патч. Для Dota 2 допускается ничья в BO2. Коэффициенты на расчёт не влияют. Все результаты этой модели остаются в локальных снимках.
3. Историческая проверка идёт по датам с двухдневным зазором. Отчёт хранит контрольные суммы исходных файлов, Brier, Log Loss, точность наиболее вероятного исхода и данные для диаграммы калибровки. При доступных котировках сравниваются одни и те же матчи. Старая эвристика сравнивается приближённо через правило короткой формы.
4. Локальная диагностика хранит показатели охвата заданного списка соревнований, качество данных по отдельным матчам, данные об ошибках и исторические метрики. HTML читается с диска и не является маршрутом Vercel.

## Запуск

```powershell
node --test tests/*.test.mjs
node scripts/update-sports.mjs --shadow
node scripts/backtest-sports.mjs --openfootball
node scripts/backtest-sports.mjs --market-dir <каталог-с-разрешёнными-CSV>
node scripts/sports-diagnostics.mjs .sports-update/<run>/diagnostics.json .sports-update/<backtest>/report.json

В проектном каталоге `.sports-update` появляются локальные снимки, история входных данных для оценки и отчёты. Для нового прогона создаётся новый каталог. Публикация через текущий GitHub Actions по-прежнему использует штатный `--preview`. Обновление сайта этой веткой требует согласования.

## Результаты исторической проверки

В openfootball нашлось 4 405 результатов отложенного периода 2024/25–2025/26 по шести дивизионам Англии, Германии и Испании. Для 3 856 матчей модель имела достаточно истории. На этих же матчах Brier составил 0,626 у Elo и 0,646 у фиксированной базы, Log Loss — 1,041 и 1,069 соответственно. На 807 матчах, где правило короткой формы также давало выбор, самый вероятный исход Elo совпал с результатом в 51,5% случаев, выбор короткой формы — в 48,0%. Это приближённое сравнение с одним правилом, так как полный старый процесс включает отбор по дополнительным условиям.

В первом запуске использование общего репозитория openfootball оставило часть сезонов недоступной. В следующем этапе используются национальные индексы издателя. Football-Data вернул HTTP 503 при проверке архива коэффициентов. Условия источника ограничивают автоматизированное использование, поэтому загрузка заменена импортом разрешённых локальных CSV. Сравнение с рыночным фаворитом и оценка точности для остальных видов спорта пока не получены.

### Сравнение моделей

Восстановленные архивы содержат 7 421 результат с июля 2024 года. Отдельный набор сравнения моделей состоит из 1 819 матчей сезона 2025/26. На сезоне 2024/25 рассчитаны вероятности для настройки калибровки, а отложенный сезон используется только для оценки. Оба расчёта получают только завершённые матчи с двухдневным зазором. Для региональных лиг проводится отдельное сравнение до и после 1 января 2025 года, поскольку в источнике доступен один сезон.

| Восемь национальных дивизионов | Elo и модель атаки и защиты по счёту | 1 819 | 0,62571 → 0,62165 | 1,04146 → 1,03526 |

95%-е интервалы парных разниц оценены повторной выборкой календарных недель. Для Brier на национальной выборке интервал −0,00804…+0,00035, для региональной −0,01469…+0,00083. ## История и модель короткой формы

Сравнение использует календарь `c2b20e1` от 22 ноября 2026, 01:13 МСК и результаты, полученные к 01:34:26 МСК, до начала событий. Повторный сетевой запуск остановили тайм-ауты 365Scores. Для штатного процесса защита сохранила статус блокировки. Архивный повтор использует сохранённые данные обеих сторон сравнения. В предыдущем отчёте отдельно не измерялось число матчей с хотя бы одной записью для каждого участника.

В локальном архиве 2 074 результата и 75 карт Dota 2. Снимки содержат ID, время или явно обозначенную точность до дня, источники, момент фактического получения и контрольную сумму. При несовпадении итогового счёта или конфликте ID запись исключается из модели. Даты без времени допускаются с двухдневным зазором. К участникам привязываются данные из той же лиги или серии, с явными заменами названий. Вклад предыдущего сезона снижен. Новые оценки остаются пробными.

- В футболе отдельный бэктест не передавал сезонные архивы модельному запуску. Подключены архивы Англии, Германии и Испании из индексов openfootball и результаты полного текущего сезона OpenLigaDB. Появились расчёты для Premier League, Championship, 2. Bundesliga, 3. Liga и Regionalliga Nord. Из оставшихся 47 матчей для 39 не хватает истории, у 8 есть только часть сопоставимой истории.
- В теннисе установлено крытое твёрдое покрытие для одиночного ATP Finals. Для Зверева и Алькараса в сохранённых источниках не оказалось сопоставимой сверенной истории. TDI публикует официальный архив и ограничивает автоматический сбор и модельное использование согласно разделу 6 условий. Старый архив Jeff Sackmann в исходном репозитории недоступен. Парные матчи требуют отдельных данных и модели.
- В волейболе сезон SuperLega определяется по календарю лиги. В сохранённой выборке у Modena и Cisterna по две игры. Для модели требуется по три. Сезонные протоколы Lega Pallavolo используются при доступности. Страница Volleyball World проверена как возможный источник, новый загрузчик для неё не подключён.
- В CS2 форматы BO3 и BO5 сохранены для 13 подтверждённых серий. Сверенной истории не хватило ни одной паре. Модель рассчитана на исход серии и не требует списка карт. Неизвестный патч указан как ограничение.
- В Dota 2 отдельно хранятся карты OpenDota и результаты завершённых серий. Например, по совпадающим названиям PARIVISION и Team Liquid найдено 14 и 2 карты соответственно, а подходящих серий нет. У семи предстоящих встреч не подтверждён формат. Победы на отдельных картах не превращаются в результаты серии.

Подтверждение теперь отличает официальный источник в пределах конкретной лиги, независимые известные первоисточники, совпадающие публикации с неустановленным происхождением, один вторичный источник, противоречия и недостаток сведений. Подтверждение из официального источника применяется в исследовательском режиме. Для двух перепечаток с одним известным первоисточником отдельный голос не считается. Ненайденные сведения о происхождении не трактуются как доказательство независимости.

На 1 819 общих матчах национальных дивизионов Brier модели короткой формы составил 0,62193 против 0,62571 у Elo, Log Loss — 1,03456 против 1,04146. Недельный 95%-й интервал Brier включает ноль, интервал Log Loss составляет −0,01237…−0,00093. На 587 региональных матчах Brier составил 0,63522 против 0,63875, Log Loss — 1,05470 против 1,05972. Вне общей выборки модель смогла рассчитать ещё 199 национальных и 37 региональных матчей. По другим видам спорта бэктест не проведён. Результаты этого этапа не оценивают калибровку новых расчётов за пределами футбола.

## Следующие этапы

- Проверить долгосрочную доступность открытых источников, расширить подтверждение календарей за пределами текущих стран и добавить контролируемый поиск новых поставщиков. Для малоизвестных лиг сначала обеспечить устойчивые идентификаторы и полную историю протоколов. В исследовательском режиме OpenLigaDB даёт немецкие национальные и региональные лиги, OpenDota даёт отдельные завершённые карты. Карты OpenDota не учитываются как сыгранные серии или сведения о патче.
- Подключать составы, новости и статистику по мере появления проверяемых адаптеров. Для тенниса нужны покрытия, подача и приём. Для киберспорта нужны версии игры, составы и карты. Текущий расчёт использует результаты встреч и проверенный контекст, когда он доступен.
- Накопить снимки до начала матчей и добавить последующее сопоставление исследований с фактическим результатом. Калибровать на отдельном периоде и оценивать на следующем, включая региональные и любительские лиги. Сравнить с рыночными вероятностями на совпадающих матчах.
- Подключить проверенные выводы к «Разбору дня» и архиву сайта после валидации. Для закрытой страницы на сайте понадобится серверная авторизация. Текущая диагностика доступна локально.

## Архивное исследование от c363dbe

Для CS2, Dota 2, тенниса и волейбола добавлен отдельный от публичного обновления запуск
`scripts/backtest-archive-sport.mjs`. Он фиксирует SHA-256 исходных файлов, отдельно показывает
число пригодных записей, охват каждой модели и метрики на одних и тех же событиях.
У контроля два варианта из c363dbe — Elo по сезону и турниру, а также модель короткой формы.
Кандидат сохраняет рейтинги между сезонами. В одиночном теннисе рейтинги разделены по туру,
покрытию и BO3/BO5; уровень соревнования выделен в отчёте. В командных видах сохраняются
границы соревнования. В киберспорте сохранены границы формата и патча.

Подбор параметров по отложенному сезону не проводился. Для тенниса использованы только
результаты соревнований, начавшихся более 30 дней до прогнозируемого турнира.
В CSV указана дата турнира, поэтому испытание моделирует оценку перед турниром.
Время появления и последующих исправлений исторических данных не известно.
Для прочих архивов используется дата завершения с двухдневным зазором.

```

Локальный JSON-экспорт содержит поля `origin`, `url`, `rights` и `rows`.
Каждая строка указывает стабильные ID матча, команд и соревнования
(`id`, `home`, `away`, `competition`), сезон, даты `date` и `completedDate`,
статус `completed`, итоговый `score` в порядке сторон.
В CS2 и Dota 2 обязательны `unit: "series"`, `bestOf` и подтверждённый `patch`.
Опциональные `rosters` из двух пятёрок ID сверяются по сторонам и уникальности, учитываются
в показателях полноты и не используются как признаки модели.
В волейболе требуются `unit: "match"`, сезон `YYYY` или `YYYY-YYYY` и очки всех сетов в `sets`.
Импорт из нескольких файлов одного источника исключает противоречащие дубликаты.
Сопоставление по ID выполняется в границах одного поставщика. Заявленные права и
соответствие ID каноническим сущностям проверяются при подготовке разрешённого экспорта.

## Локальное накопление и оценка

`collect-sports-research.mjs` запускается отдельно от штатной публикации. Один
запуск опрашивает источники, сохраняет открывшиеся расписания и результаты,
рассчитывает предварительные вероятности, сверяет старые оценки и строит отчёт.
Для ежедневного режима внешний исполнитель может вызывать ту же команду из одной
и той же рабочей копии. Новое задание и production-расписание не активированы.
Для запросов действуют кэш и паузы после HTTP-ошибок. OpenLigaDB опрашивается по
документированному маршруту изменений тура. Сезонный снимок обновляется не чаще
раза в неделю, между обновлениями проверяется ближайший тур в окне календаря.
При ошибке источник отражается в диагностике. Отложенные игры из старых туров
могут появиться только при очередном обновлении сезона или в дополнительном файле.

```powershell
node scripts/collect-sports-research.mjs collect
node scripts/collect-sports-research.mjs report
node scripts/collect-sports-research.mjs report --markdown
node scripts/collect-sports-research.mjs replay <checkpoint.json> <snapshot-directory> <ISO-cutoff>
node scripts/collect-sports-research.mjs report replay --markdown
```

Каталог `.sports-update/daily-research-v1` хранит отдельно исходные тела ответов,
нормализованные наблюдения, ссылки на признаки моделей и манифесты прогонов.
SHA-256 проверяется при чтении журнала. Манифест публикуется локально атомарно
после записи объектов. Успех, ошибка, кэш, время получения, пропуск по свежести и
следующая допустимая попытка сохраняются в записях запросов. Повтор контрольных
данных пишет только в `daily-research-replay-v1` и не пополняет проспективную
выборку.

Разрешённые наблюдения других издателей можно передать после `collect`
локальными JSON-файлами с `capturedAt`, описанием прав `rights` и массивом
`rows` в формате адаптеров `sports-sources.mjs`. Для каждой записи нужны
имя издателя, его ID события, HTTPS-ссылка, вид спорта, турнир, участники,
старт в миллисекундах UTC и статус. Для состоявшихся встреч указывается счёт.
Сведения о поставщике, идентификаторы сторон, формат и контекст соревнования
следует передавать, когда они подтверждены. Устаревшее расписание из файла
старше двух суток исключается. Импорт серий и протоколов
`import-sports-archive.mjs` по-прежнему даёт отдельный архив для бэктестов.
Мост между этим архивом и живым календарём требует доказанного соответствия ID.

Для одного события и версии модели в оценку входит первая сохранённая
вероятность, полученная более чем за 10 минут до старта. Событие наследует
идентификатор при повторном наблюдении того же ID издателя с теми же
участниками и соревнованием. При отсутствии такого ID сопоставление требует
точного совпадения соревнования, нормализованной пары и времени. Перенос,
противоречащие результаты и несовпадение формата оставляют запись на проверке.
Результаты с точностью до дня могут обучать модель при действующих ограничениях,
а для расчёта оценки качества требуются точное сопоставление и подтверждение
официального источника либо независимых источников. Оценка хоккея относится к
исходу полного матча. Карты OpenDota никогда не становятся исходами серий.

В отчёте отдельно показаны охват, пропуски, статус результата, объём выборки,
Brier, Log Loss и интервалы калибровки. Модели сравниваются на общих матчах
с оценками из одного прогона. Разбивка по уровням использует категории
текущего справочника соревнований. Срезы за 7 и 30 дней включают предыдущий
период, численность и описательную разность метрик. Неполные окна помечаются.
Статусы готовности опираются на описанные выше испытания. Сезонная историческая
проверка проведена для футбола и одиночного тенниса. Надёжность калибровки
для допуска и готовность к ограниченному внедрению пока не подтверждены ни для
одного вида спорта.

На фактическом сетевом прогоне удалось накопить 2 410 нормализованных результатов
и 80 карт. На 16 точных футбольных событиях не хватило независимого подтверждения
расписания. Первых проспективных вероятностей с подтверждённым исходом пока нет.
На отдельно сохранённом контрольном календаре повтор воспроизвёл 35 оценок —
9 футбольных, 8 баскетбольных, 18 хоккейных. Для ежедневного охвата остальных
видов нужны разрешённые источники календаря и результатов. OpenDota поставляет
карты, а openfootball — исторические результаты и подсказки дат. Ни один из
этих источников не подтверждает сам себя через другой адрес.

### Каталоги, резервирование и восстановление

Для регулярного запуска используется постоянный путь `SPORTS_RESEARCH_STORE`
на отдельном локальном томе с поддержкой жёстких ссылок, например NTFS.
Резервная копия должна быть на другом физическом носителе. Публикуемый манифест
ссылается на объекты по SHA-256. Объект записывается во временный файл,
синхронизируется с файловой системой и публикуется без перезаписи.
Копирование сначала проверяет и переносит объекты, затем манифесты.
Повтор копирует только отсутствующее содержимое. Повреждённый объект
отклоняется. Восстановление после повреждения выполняется в новый каталог.
Незавершённые временные файлы не читаются как записи журнала.
Если процесс аварийно завершён, перед снятием оставшейся блокировки
`collect.lock` нужно убедиться, что запустивший её процесс действительно завершён.

Пример ручной проверки конфигурации и прогона на Windows.

```powershell
pwsh -NoProfile -File scripts/run-sports-research.ps1 -Store D:\SportsResearch -Backup E:\SportsResearchBackup -ValidateOnly
pwsh -NoProfile -File scripts/run-sports-research.ps1 -Store D:\SportsResearch -Backup E:\SportsResearchBackup
$env:SPORTS_RESEARCH_STORE = 'D:\SportsResearchRestored'
node scripts/collect-sports-research.mjs restore E:\SportsResearchBackup
node scripts/collect-sports-research.mjs verify
node scripts/collect-sports-research.mjs report --markdown
```

PowerShell-обёртка назначает один ключ запуска на дату UTC, пишет диагностику и
ошибки в `logs`, затем создаёт проверяемую копию. Повтор не повторяет запросы
уже сохранённого прогона. После отдельного согласования эту команду можно
поставить в Планировщик заданий Windows с правилом «не запускать новый экземпляр»
и рабочей папкой закреплённой исследовательской ветки. Нужны всегда доступный ПК,
разные физические носители и проверенное восстановление под той же учётной
записью. Дальше нужно подтвердить доступ к автоматически обновляемому календарю,
вести наблюдение за ошибками и дождаться реальных расчётов с проверенными исходами.

Vercel и GitHub остаются в цепочке сайта и кода. GitHub-hosted runner
использует временное окружение, Vercel Functions не дают постоянного диска
для журнала, а расписание GitHub Actions работает с веткой по умолчанию.
Поэтому здесь используется выделенный локальный диск и внешний планировщик.
Сетевое хранилище или отдельный хост можно рассмотреть при необходимости
работы независимо от ПК. Архив в Git не включается.
[GitHub-hosted runners](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners),
[события GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows),
[Vercel Functions](https://vercel.com/docs/functions/runtimes).

## Автономные прогоны после fbb0e55

Условия DFB запрещают неавторизованный автоматизированный сбор веб-данных.
Документированного публичного API официальных расписаний, доступного этому
проекту без отдельного договора или разрешения, не найдено. Виджеты DFB
предназначены для показа, а не для получения данных движком. DFBnet
документирует CSV-выгрузку расписания для пользователей с правами на турнир.
Указанная выгрузка не содержит результатов состоявшихся матчей.
Поддерживаемый путь — получить разрешённый официальный поток или экспорт
и согласовать его формат. Разрешённый поставщик может складывать
нормализованные манифесты в выделенный входящий каталог. Скрипт читает
завершённые `.json`, хранит исходные байты и выбирает последнее наблюдение
издателя по событию. Ошибка в одном файле записывается отдельно.
Автоматическая доставка DFB и преобразование конкретного CSV пока отсутствуют.
Шесть ручных наблюдений DFB не участвуют в проверке доступности автоматического
потока. [Условия DFB](https://www.dfb.de/nutzungsbedingungen) ·
[Экспорт в DFBnet](https://portal.dfbnet.org/de/service/online-hilfe/meisterschaft/spielplanbearbeitung/spielplan).

### Повторы и восстановление

- PowerShell назначает четырёхчасовой ключ UTC. Последующий ключ в тот же день
  может добавить наблюдения. Повтор успешно сохранённого ключа восстанавливает
  отчёт и резервную копию. При полном отсутствии новых ответов и временной
  ошибке сохраняется отдельная попытка с кодом возврата 3. После паузы
  та же очередь может сохранить новую попытку. Отдельный источник, который
  прервался при частично успешном сборе, повторно опрашивается в следующем
  интервале с учётом рекомендованной задержки.
- После суток без пригодного снимка OpenLigaDB заново запрашивается сезонный
  календарь. Подтверждённые результаты можно подхватить из актуальных ответов.
  Вероятности за пропущенное время задним числом не создаются.
- Блокировку каталога на Windows держит именованный канал ОС. После
  завершения процесса или перезапуска системы канал освобождается. Старую
  файловую блокировку сборщик снимает только при однозначном отсутствии её
  процесса. Нечитаемая блокировка, занятый или повторно использованный PID
  оставляют сбор остановленным. Канал действует на одной машине. Каталог
  хранилища не рассчитан на одновременную запись с нескольких компьютеров.
- Объекты, опубликованные до отключения, проверяются по SHA-256. Неполные
  временные файлы и объекты без сохранённого манифеста не создают наблюдений.
  При неудачном резервировании завершённый снимок остаётся на основном
  диске. Задание завершается ошибкой и на повторе того же ключа снова
  создаёт резервную копию без дублирования сохранённого снимка.

Проспективный отчёт отдельно считает матчи до начала, матчи без сверенного
исхода, подтверждённые исходы и конфликты идентификаторов или времени.
Первая сохранённая вероятность остаётся исходной для оценки. Метрики
выводятся начиная с 30 сверенных событий в соответствующей выборке модели,
периода, уровня или парного сравнения. Этот порог позволяет показывать
описательные показатели. Он не удостоверяет статистическую значимость.

### Задание Windows без регистрации

```powershell
pwsh -NoProfile -File scripts/prepare-sports-research-task.ps1 `
  -Store D:\SportsResearch -Backup E:\SportsResearchBackup `
  -TaskUser 'COMPUTER\ResearchUser' -OutputFile .sports-update\research-task.xml
```

Скрипт проверяет настройки через объект Windows Task Scheduler и сохраняет
XML с `Enabled=false`, интервалом четыре часа, `IgnoreNew`,
`StartWhenAvailable` и тремя повторами через 30 минут. При наличии разрешённого
потока можно передать `-Inbox`. Для фоновой работы после будущей регистрации
выбранной учётной записи потребуется право запуска пакетного задания, доступ
к Node.js, PowerShell, рабочей копии, дискам и сети. Пароля в XML нет. Он
вводится в Windows при регистрации, если этого требует выбранный режим.

Если ПК выключен, сбор невозможен. После включения Windows может выполнить
догоняющий запуск с текущим ключом. Для спящего компьютера по умолчанию
ожидается пробуждение. Параметр `-Wake` разрешает запрос таймера пробуждения,
если это поддерживают оборудование и режим питания.
[Настройки Windows Task Scheduler](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-schema).

Для контрольной серии выполните `run-sports-research.ps1` дважды с одной
величиной `-RunKey`, затем с другой. Сверьте `collect-sports-research.mjs verify`,
отчёты и журналы резервирования. В живой серии два разных интервала
добавили две записи к существующей, а неудачная копия второго интервала
на повторе восстановилась без дублирования. Шесть ранее сохранённых
оценок остались с прежними временами, подтверждённых исходов не было.
Проверены принудительное завершение дочернего процесса, конкурирующий
запуск и переходы при временном сбое. Реальное отключение питания и
пробуждение физического компьютера не выполнялись. Конфигурация проверена
без регистрации и активации задания.
